# 系统设计说明

## 1. 目标

系统采用 Linux C 客户端/服务器架构，通过 TCP 网络完成登录、图书检索、借阅及管理操作。服务器是权限和数据一致性的唯一可信边界，客户端只负责输入、展示和请求发送。

## 2. 结构

```text
library-system/
├── server/main.c              服务器入口
├── server/app.c               服务端网络、业务逻辑和 JSON 持久化
├── server/app.h               服务端应用接口
├── client/main.c              客户端入口
├── client/app.c               命令行界面与客户端协议实现
├── client/app.h               客户端应用接口
├── data/                      运行数据
├── tests/fixtures/            与运行数据隔离的测试数据
├── tests/integration_test.py  自动化网络集成测试
├── docs/                      设计、协议和测试文档
├── Makefile                   构建、检查和测试入口
└── README.md                  使用说明
```

## 3. 运行架构

服务器主线程执行 `socket -> bind -> listen -> accept`。每个客户端连接由独立 pthread 处理，连接内维护 `ClientSession`。除 `PING` 和 `LOGIN` 外的请求必须先通过登录校验。

## 4. 数据模型

- 用户：ID、用户名、密码、姓名、角色、启用状态。
- 图书：ID、ISBN、书名、作者、出版社、分类、总册数、可借数、位置、状态。
- 借阅记录：记录 ID、用户 ID、图书 ID、借出/到期/归还时间、续借次数、状态。
- 操作日志：日志 ID、操作者、角色、操作、结果、消息和时间。

图书状态为 `NORMAL` 或 `DISABLED`；借阅状态为 `BORROWED`、动态计算的 `OVERDUE` 或 `RETURNED`。

## 5. 并发与一致性

所有会修改 JSON 的借阅和管理操作均持有 `data_mutex`。检查库存、创建借阅记录和减少库存处于同一临界区，保证只剩一册时至多一个客户端成功。JSON 使用“临时文件写入 + rename”替换，避免产生半截文件。服务器启动时根据有效借阅记录重新核对 `available_count`。

## 6. 权限模型

- `READER`：查询、借书、还书、续借、查看本人记录。
- `ADMIN`：拥有读者能力，并可管理图书、读者、全部借阅记录和日志。

权限始终由服务器验证，隐藏客户端菜单不能替代服务端鉴权。

## 7. 已知限制

这是课程演示项目，当前以 JSON 文件而非数据库持久化，密码为明文，TCP 未使用 TLS。生产环境应使用密码哈希、数据库事务、TLS、分页和连接限流。
